# Skill: 反思与 Skill 自优化（Reflection）

## 概述

在完成用户请求的过程中或结束时，**自动**留意值得沉淀的经验，提炼成精炼、可复用的内容，用于新增或优化 `.agents/skills/` 中的共享 skill，或必要的跨工具入口文档。目的：让 agent 随使用持续变得更贴合本项目与用户习惯。

适用文档范围：`AGENTS.md` 与工具专属薄入口（入口与权限边界）、`.agents/skills/*/SKILL.md` 及其 references（工作流 / 实现规范 / 组织规范）、项目领域文档，以及必要时新建的专题文档。

---

## 一、何时触发反思

在以下信号出现时，提炼一条候选经验：

- **纠正性反馈**：用户指出某次做法不符合预期（"太大了""没和我确认""不该这样做"）
- **工作方式偏好**：用户表达了对「agent 该怎么工作」的偏好（沟通、拆分、确认时机、输出风格）
- **确认后的良好做法**：某个方案经用户认可、值得固化为默认做法
- **重复出现的模式**：同类问题/决策在多次会话中反复出现，值得写成规则
- **踩坑**：因缺少某条约定而走了弯路或返工

> 单纯一次性的、仅对本次任务有意义的信息**不要**沉淀（那是上下文，不是 skill）。

---

## 二、如何提炼

1. **从个例抽象到原则**：去掉本次特定的文件/数值/场景，写成下次遇到同类情况可直接套用的规则
2. **精炼**：一两句话说清「什么情况 → 怎么做」，附必要的「为什么」
3. **定位归属**：判断这条经验属于哪个 skill 文档的哪一节
   - 「怎么实现新功能 / 怎么和用户协作」→ `WORKFLOW.md`
   - 「某个 AI 工具如何读取项目规则」→ `setup/adapters/registry.json`、`AI_TOOL_ADAPTERS.md` 与对应薄入口
   - 「怎么重构 / 代码质量检查」→ `Optimize.md`
   - 「某一业务领域的规则」→ 对应 `project-domain-*` reference
   - 跨度大、自成体系 → 新建专题文档并在共享入口建立引用
4. **去重**：先搜索目标文档是否已有相同/相近条目，有则改进措辞而非新增

---

## 三、冲突与确认协议

- 明确、行为保持且不冲突的去重、纠错或补充可直接写入并说明。
- 有冲突、影响范围大或归属不明确时，先给出拟定内容和目标位置，确认后再写。
- 个人偏好交给 `team-member-preferences`，不得升级为团队通用规则。

---

## 四、输出格式

收尾时只报告实际写入或仍需确认的候选：

```
## 反思（候选 skill 更新）

- **经验**：<提炼后的精炼规则（什么情况 → 怎么做，附为什么）>
- **归属**：<目标文档 · 章节>
- **与现有内容关系**：补充 / 与「xxx」冲突需取舍 / 不确定
- **处置**：已直接写入 ／ 待你确认最终版本后写入
```

无候选经验时不必输出本节。
