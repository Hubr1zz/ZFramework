# Agent 工作流快速上手

你只需要记住一件事：直接告诉 AI 你想做什么。普通任务不需要背命令，也不需要先了解 OpenSpec。

## 打开工作台

在 Unity 顶部菜单选择：

```text
Tools → Agent Workflow → Agent Workbench
```

工作台里最常用的是：

- **导入报告**：查看刚从设计文档整理出来的计划。
- **设计文档树**：点击“工程能力”旁边的入口。在页面顶部添加、替换或移除一个或多个包含 Markdown 的设计文档路径；不需要再配置单独的文档根目录。项目会创建并维护 `openspec/implementation-ledger.json`，至少一个路径有效时点亮右上角桥接灯。每个路径显示为独立顶层节点并支持逐层折叠；“检查”会发现新增/删除文件并重算指纹，新文档默认显示 0%。
- **指令列表**：查看设计导入、实现后文档及时性检查、Spec 翻译、apply、sync 与归档等可直接输入给 Agent 的标准指令。
- **OpenSpec**：查看已经批准的计划和正式说明。
- **增量维护**：查看以后需要整理的代码问题。
- **关系图谱**：位于顶部“刷新”右侧；节点颜色区分 System / Feature，选中后可查看依赖和核心实现思路。阻塞项可点击定位依赖节点，待合入项可点击打开所属 Change。
- **工程能力**：位于关系图谱右侧；查看 Plugin、Architecture、System。可在 Plugin 详情填写使用判断依据；Architecture 是锁定的强制复用能力，修改前需先与用户确认。
- **代码索引**：主入口页签；手动异步构建 `Assets` 下全部 C# 派生索引，并显示进度、覆盖率、增量提取/复用数量、缺失项和解析统计。索引仅保存在本机，不进入 Git。

右上角可以切换浅色/深色主题；深色模式会使用更清晰的按钮和控件线框。

## 直接提出需求

像平时说话一样描述目标即可，例如：

```text
解释一下现在的核心状态流程。
修复列表状态没有正确恢复的问题。
重构角色状态同步流程，不要改变外部行为。
```

AI 如果缺少关键条件，会先问你；不需要你提前把所有细节写完整。

在 `Assets` 或配置的项目内源码根包含 C# 的 Unity 项目中，setup 会在 PowerShell 7+ 可用时安装本地代码结构查询，不要求 `Assets/Scripts`。Windows 和 macOS 共用 UTF-8 可移植索引；AI 必须先用一次查询定位完整类型、调用者和改动影响，再只读取少量命中源码。缺少 `pwsh` 时，setup 会先征求许可再尝试安装，失败则回退原生检索。

## 导入设计文档

想把设计文档整理成开发计划时，告诉 AI：

```text
设计导入：角色成长系统
```

如果 Workbench 当前语言与 Spec 权威语言不同，输入：

```text
翻译现有Spec：英文
```

工作台只显示已经与权威文件同步的译文；出现“请同步”时，点击按钮复制增量同步指令即可。

Spec 条目名称可在中文和英文界面下分别右键或双击重命名。名称只影响当前语言的列表与引用显示，不改变 capability ID、路径或依赖关系。

如果要导入全部内容，可以说：

```text
设计导入
```

导入完成后，到工作台的“导入报告”查看结果。导入只会生成等待确认的 Draft Change，不会立刻修改代码，也不会直接生成正式 Spec。

## 检查并修改计划

进入一条导入记录后，默认先显示批次信息和导入提示；点击左侧 Spec 条目查看具体提案，点击返回按钮右侧的“导入记录信息”可切回。打开 Draft Change 时重点看它要实现什么、有哪些规则、还缺什么。

- 批次级不确定项默认隐藏；点击“显示提示”可分类查看，并可直接跳到来源文档行。
- 出现 **Blocking**：必须先解决。
- 出现 **Warning / Info**：确认你理解并愿意接受后，才能接受它。
- 在审核表格右侧填写“接受备注”并勾选该行；Blocking 行不能勾选，必须先解决。
- 内容不对：直接告诉 AI `修改<id>: 你希望怎样修改`。
- 有仅在实现时生效的补充要求：点击“备注”保存；apply change 会在编码前读取。
- 内容确认无误：在工作台批准这条 Change。

不确定某条提示是什么意思时，先让 AI 用自然语言解释，不要急着接受。

## 开始实现

批准后，直接告诉 AI：

```text
实现 <change-id>
```

实现和检查完成后，你也可以直接说“同步正式 Spec 并归档这条 Change”。AI 会按顺序完成后续步骤，不需要你记住内部命令。

这两个步骤彼此独立，不会由 `apply` 自动触发：

1. 手动执行 `sync specs <change-id>`。如果正式 Spec 在 Change 建立后被创建、删除或修改，AI 会比较基线、当前内容和 Delta；不重叠内容继续保留式合并，只有可能覆盖功能或混杂语义时才停止并提醒你。
2. 回到 Change 详情。所有 Tasks 完成且同步成功后，“归档”按钮会启用。点击后 Change 会移入带日期的历史目录，文件仍可手动查看；“删除”则是永久移除。

就这些。日常使用时，你负责说明目标和确认结果，AI 负责读取项目、整理计划、实现和核验。
