# Design Import Type Filters

类型参数是 Requirement 的包含过滤器，不是来源文本删除器。多个参数取并集；未传参数表示全部类型。

类型参数只决定从设计来源提取哪些设计 Requirement，不禁止生成实现规划。只要输出包含 `game-rule`，就仍必须生成对应的 Feature 实现 Draft；该 Feature 的总括 Requirement 是对规则设计的实现引用，不算把未选择的“内容”或“美术”设计混入结果。

统一文本中，冒号后到第一个 `--` 前的内容是范围；`--规则`、`--内容`、`--美术` 是独立参数，不属于范围。重复参数去重，未知参数报错。

## 参数

| 统一入口 | 兼容 CLI | 进入 Requirement 的内容 |
| --- | --- | --- |
| `--规则` | `--filter rules` | 可复用的系统规则、玩法机制、状态转换、公式、约束和失败条件 |
| `--内容` | `--filter content` | 具体且被创作出的游戏内容、实例、配置、数值、文案和命名对象 |
| `--美术` | `--filter art` | 视觉、动画、特效、音效、相机、UI 表达及游戏内呈现形态 |

## 分类

### 规则

判断该描述是否脱离具体内容实例后仍成立，并能约束一类玩法行为。

- 包含：系统流程、触发条件、输入输出、状态、公式、资源循环、通用接口和内容制作约束。
- 不包含：某个具体关卡、角色、道具、数值实例或具体表现资产。
- 例：`环境区域会对玩法产生附加规则，也可以与特定敌人机制组合。`

### 内容

判断该描述是否定义一个具体可配置、可命名或可制作的游戏实例。

- 包含：具体环境效果、角色、敌人、能力、道具、事件、数值表、文案和关卡实例。
- 不包含：仅说明这些实例共同遵守的通用规则。
- 例：`冰面：处于冰面上的单位移动距离 -1。`

### 美术

判断该描述是否定义玩家如何看见、听见或感知系统与内容。

- 包含：特效、动画、音效、相机行为、UI 布局与反馈，以及概念在游戏中的载体。
- “能量点数显示为文字、多个 Sprite 或专属 3D 物件”属于美术/表现决策，即使它同时影响 UI 数据绑定。

## 混合描述

逐句或逐子句分类，不要按整段或整页分类。

- `先播放特效，再造成伤害` 同时包含美术事件和规则顺序。
- 只选 `--规则` 时：生成“伤害必须等待表现完成信号后结算”的顺序/接口契约；不规定特效的颜色、粒子或动画内容。
- 只选 `--美术` 时：生成特效的触发与完成反馈要求；把“完成后允许伤害结算”保留为接口边界，不重新定义伤害公式。
- 同时选择 `--规则 --美术` 时：两侧都生成，并通过 dependency 或同一 Scenario 的时序连接。

## 跨层约束

未选类型不能成为独立 Requirement，但以下信息不得丢失：

- 执行先后、等待完成或取消/中断语义；
- 规则层与表现层之间的事件、信号或数据接口；
- 某表现是否是功能可操作、可理解或可验收的必要条件；
- 具体内容暴露出的系统容量、扩展点或配置需求。

把这些信息放入最相关的选中 Requirement、capability dependency，或 `run.json.typeFilterAudit.preservedConstraints`。只保留约束，不扩写未选类型的具体方案。

## 输出审计

在 `run.json` 的 `typeFilters` 与 `typeFilterAudit` 记录：

- 本次选择的类型；无参数时写“全部”；
- 未生成独立 Requirement 的类型；
- 从未选类型保留的跨层约束及来源；
- 无法可靠拆分的混合描述写入 `mixedDescriptions`；只有它构成缺失依赖时才创建 Gap，不得把一般歧义伪装成 Gap。
