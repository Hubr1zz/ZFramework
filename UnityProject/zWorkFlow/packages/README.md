# 可拆分工作流包

完整工作流按三层组合：

| 层 | 包 | 可独立工作 | 职责 |
| --- | --- | --- | --- |
| 文档维护层 | `document-workflow/` | 是 | 设计文档、知识库、术语、灵感、案例与历史 |
| 项目层 | `zWorkFlow/` 根包 | 是 | 项目事实、OpenSpec、实现、重构、团队和 Unity 工作台 |
| 中间层 | `document-project-bridge/` | 可选 | 项目侧维护实现后变更账本，检查“已实现后又修改”的设计文档，辅助用户决定是否重新设计导入 |

文档包和项目包互不依赖。项目包在 `openspec/implementation-ledger.json` 维护实现基线与变更审计，全部设计文档路径只保存为项目侧本机偏好；中间层以至少一个有效来源建立桥接，每个来源独立展示可折叠文档结构，刷新时重扫新增/删除 Markdown 并计算实现后变更，不自动调用项目工作流，也不向文档包写入工程状态。
