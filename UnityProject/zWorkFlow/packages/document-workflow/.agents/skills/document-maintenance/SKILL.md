# Document Maintenance

本 skill 是独立文档包的完整流程源。先根据项目事实调整目录名称和文档规则，不要假设特定游戏或框架。

## 核心流程

1. 读取文档包入口、目录地图和目标文档。
2. 用 `rg --files` 与 `rg` 搜索相关正式文档、术语、灵感和案例。
3. 区分：
   - 已确认正式设计
   - 草稿 / 灵感
   - 稳定术语
   - 内容案例
   - 未解决问题
4. 实质修改正式设计前，审查设计完整性与实现清晰度；缺少核心行为时先询问用户。
5. 编辑后维护链接、待办和内容修改历史。纯工作流改动不写内容历史。
6. 不覆盖已有文档、个人规则或历史；冲突时列出差异。

## 与项目包桥接的边界

文档包不保存工程实现状态。`implementation-ledger.json` 由已安装 bridge 的项目包在 `openspec/implementation-ledger.json` 维护，文档包不得创建、读取、更新或要求该文件。

当用户明确要求“检查需求变化”时，文档包可以提供变更后的 Markdown 作为只读输入；项目侧负责读取对应代码、判断语义并在确认无需求变化时更新项目账本。确认有语义变化时，项目侧保留“有改动”状态并由用户决定是否执行设计导入。

文档包在没有桥接 skill、项目包或 Unity 时必须能完整独立工作；任何 Markdown 仓库都可被项目包作为只读桥接来源。
