## Context

资源点配置已经包含生成权重、地块容量、同类上限、翻牌数和素材池，但首次生成与恢复分别只实现了部分约束。功能需要保证同一冻结 RoutePlan 在首次翻图和读档后都产生合法、同义的资源点集合。

## Goals / Non-Goals

**Goals:**

- 消除随机重试造成的意外欠填，同时保留权重与同类上限。
- 在 Bundle 准备时消除资源点稳定 ID 歧义。
- 在发布恢复候选前严格核验资源点配置一致性，并兼容旧单素材快照。

**Non-Goals:**

- 不定义 `0–3` 区间的数量分布或修改生产资产。
- 不让恢复接受不同 ContentBundleId 的跨版本内容迁移。
- 不改变采集 ActionQueue、3D marker 或阶段生命周期。

## Decisions

1. GameCore 每轮重建尚未达到 `maxPerTile` 的候选池，再复用既有加权选择；候选为空即结束，不使用固定重试次数。
2. Bundle 在冻结单个地块时拒绝重复配置 ID；这只约束配置定义，不禁止同类型运行态实例重复。
3. 恢复从 BoundRoute 的冻结地块配置建立 canonical 定义，按总量、同类计数、翻牌数和素材稳定 ID 多重集合校验。
4. schema v4 要求完整 `MaterialItemIds`；v2/v3 缺失该列表时，只允许可解析且属于唯一 canonical 定义的 `ItemId`，并按旧语义恢复单素材牌池。
5. 恢复只构建局部候选图，全部校验成功后才返回 runtime state；展示名始终取当前冻结配置。

## Risks / Trade-offs

- 更严格恢复会拒绝同 Bundle 内被篡改或损坏的快照 → 保留明确诊断，不静默修补当前 schema。
- 旧快照只有单个素材 ID，无法证明完整新素材池 → 仅恢复旧单素材语义，不伪造成新配置池。
- 资源点数量区间仍未表达 → 留待产品定义数量分布后单独扩展配置，不在本次猜测。
