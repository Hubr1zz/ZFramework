## Context

人口属于 Settlement 的长期状态，但救援结果在成功回营前仍可能因撤退取消、保存失败或进程退出而失效。因此它必须先成为 Hunt-owned 状态，再随唯一回营记录跨越阶段边界。

## Decisions

### 首期救援对象是匿名人口

`RescuePopulation` 只增加远征内计数，不创建 Hunter，不保存模板、名字、装备或血脉。回营后 Population 增加，玩家继续通过既有世界空间招募板选择模板并命名。

### Hunt ActionQueue 是唯一写入入口

共享事件流程只依赖 `IPlayableEventPopulationCommand`。Hunt 实现重验正数量、整数容量和当前存活小队执行者，并把提交事实放入事件 root 的 outbox；View 只读展示。

### 活动狩猎 v3 与回营 v3 分别承担阶段内和跨阶段持久化

活动快照 v3 保存非负救援计数；v2 只迁移为零，旧版本伪造新字段时失败关闭。正常撤退记录 v3携带同一计数，v0/v1/v2 均不得混写该字段。

### Settlement 以 RecordId 原子、幂等提交

GameCore 在任何写入前预检当前 Population、救援计数及加法溢出，并与参战者和全部物品检查共同冻结计划。Settlement root 只在计划有效时增加人口，并继续既有物品、成长、历史和日历提交；相同 RecordId 重试不重复增加。

### 紧急撤退不丢弃人口

首期没有已声明的人口丢失规则。远离营地时仍只从携带物选择放弃一份，同行幸存者单独显示并随任何成功普通撤退保留；未来惩罚策略应另行配置，不在此处硬编码。

## Risks / Trade-offs

- 当前遭遇/Showdown 交接仍不支持保存来源 Hunt session；旧兼容完成记录会清除 v3 救援字段以避免阻塞，但本 Change 不宣称救援人口跨该边界保留。
- 事件效果批次继续沿用既有逐项提交语义；本 Change 保证单次人口命令与整份回营计划各自失败关闭，不引入通用效果回滚。
- 只提供一条生产事件，不批量扩充人口事件或自行发明容量、死亡和关系规则。
