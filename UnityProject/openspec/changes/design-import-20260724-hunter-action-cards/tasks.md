# 实现任务

## 1. 费用领域模型

- [x] 1.1 建立可组合的纯 C# 行动卡费用定义与结算契约，覆盖时点、战斗灵感、意志和特殊费用。
- [x] 1.2 将 CharacterActionCardData 映射为不修改 SO 的运行时费用、正反面效果、恢复条件和爆发定义。
- [x] 1.3 实现费用准备与原子提交，确保取消、目标失效或任一费用失败时不会执行效果或留下部分支付。

## 2. 动态结算队列

- [x] 2.1 在行动卡 Feature 内实现纯 C# Action Queue，支持顺序执行、队首/队尾追加、暂停、恢复、取消和失败短路。
- [x] 2.2 建立 Adapter 异步执行器，将玩家选择、动画和现有效果迁移为可等待 Action，移除权威结算中的 fire-and-forget 推进。
- [x] 2.3 按“校验 → 准备费用与输入 → 原子提交 → 效果与动态步骤 → 事件、时点和翻面”接入普通使用、恢复与爆发路径。

## 3. 基础卡与意志行动

- [x] 3.1 沿用猎人 startingCards 配置创建普通行动卡实例，不为基础行动卡建立独立规则类型。
- [x] 3.2 将意志行动接入同一行动卡与队列管线，通过现有意志资源端口支付费用，并在回合边界重置其可用状态而不自动恢复已消耗意志。
- [x] 3.3 保持意志行动不可爆发，并将“转向”“硬撑”等未细化效果保留为数据占位而不猜测行为。

## 4. 验证

- [x] 4.2 为基础卡初始配置、意志不足、每回合可用状态重置、恢复与爆发不执行正面效果补齐测试。
