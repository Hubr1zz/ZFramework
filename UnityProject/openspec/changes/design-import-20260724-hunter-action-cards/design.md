# 猎人行动卡实现设计

## Context

现有 CharacterActionCardInstance 已持有卡面、效果、恢复与爆发相关运行时状态，CharacterConfigSO 也已通过 startingCards 配置初始行动卡；但费用仍未形成可组合的领域定义，CardEffectResolver 以同步循环执行效果，部分异步效果通过 fire-and-forget 启动，无法可靠表达“翻转其他卡牌作为费用”这类需要等待玩家输入并动态改变后续步骤的结算。

纯 C# 层负责确定性规则与队列状态；现有 GameManager/CombatManager 等 composition root 负责创建和连接，Adapter/ViewLayer 负责 Unity 生命周期、玩家输入、动画和其他异步表现。

## Goals / Non-Goals

**Goals:**

- 将行动卡费用从卡牌效果与实例状态中解耦，首批支持时点、战斗灵感和特殊费用。
- 以 Action Queue 顺序执行费用、效果、事件与翻面步骤，并支持等待输入、恢复执行和运行中追加步骤。
- 将基础行动卡定义为初始配置授予的普通行动卡，将意志行动定义为复用同一管线的特殊行动卡。

**Non-Goals:**

- 不在本 Change 中定义“转向”“硬撑”等具体卡牌效果。
- 不让 GameCore 依赖 UniTask、Unity 输入或表现对象。
- 暂不把 Action Queue 拆成独立 Architecture capability；出现第二个直接复用者时再提取稳定公共契约。

## Decisions

### 费用采用可组合的独立定义与结算器

运行时卡牌 SHALL 持有费用定义集合，而不是把资源扣除写入卡牌效果。每种费用通过统一契约执行校验、准备与提交：

- 时点费用通过战斗回合与时点端口读取并提交。
- 战斗灵感费用通过独立资源端口读取并提交。
- 特殊费用生成队列步骤；例如选择并翻转其他卡牌时，步骤可暂停等待合法玩家输入。

系统先验证静态条件并完成特殊费用选择，再原子提交本次已配置费用。玩家取消选择、目标失效或任一费用无法支付时 SHALL 终止出牌，且不执行卡牌效果或留下部分支付结果。

### Action Queue 持有动态结算顺序

GameCore SHALL 提供确定性的队列状态和 Action 描述；Adapter SHALL 逐项驱动执行，并在遇到玩家输入、动画或其他异步边界时等待完成后再继续。队列 SHALL 支持：

- 按顺序执行；
- 在执行期间向队首或队尾追加后续 Action；
- 暂停、恢复、取消和失败短路；
- 将费用提交、卡牌效果、事件发布、时点累计和翻面作为显式步骤，不使用 fire-and-forget 推进权威结算。

标准出牌顺序为：校验卡牌与目标 → 准备费用并等待必要输入 → 原子提交费用 → 执行卡牌效果及其动态追加步骤 → 发布结果并更新卡面。爆发路径仍不执行正面效果。

### 基础行动卡不是独立卡牌类型

基础行动卡 SHALL 继续使用普通行动卡定义与实例，只由猎人初始卡配置决定战斗开始时授予哪些卡牌。规则层不以 `isBase` 分支改变其费用、效果或生命周期；显示标签可作为非权威元数据存在。

### 意志行动复用行动卡管线

意志行动 SHALL 复用普通行动卡的配置、费用、校验和 Action Queue，以意志费用适配器消费现有战斗意志资源。其每回合可用状态由行动卡模块重置；已经消耗的意志点不因该重置自动恢复。意志行动不可爆发，其他具体效果仍由数据配置。

## 依赖

- 战斗回合与时点代码实现：提供时点提交、现有意志资源和回合边界契约。
- 战场交互代码实现：提供移动、目标选择和棋盘操作契约。

## Risks / Trade-offs

- [队列成为跨模块隐式基础设施] → 当前由行动卡 Feature 持有，并以第二个直接复用能力作为提取 Architecture capability 的门槛。
- [等待输入期间战场状态改变] → 恢复前重新校验选择与费用；失败时取消整个出牌事务。
- [原子费用与异步表现难以回滚] → 权威费用在所有准备步骤成功后一次提交，提交前表现不得修改规则状态。
- [现有 fire-and-forget 效果破坏顺序] → 逐步迁移为可等待的队列 Action，并用事件顺序测试防止回归。

## 测试

以固定输入或随机源覆盖混合费用的原子提交、特殊费用取消、动态队首/队尾追加、失败短路、基础卡初始配置、意志不足与回合重置。Unity 侧只验证配置映射、输入等待和事件顺序。
