## Context

活动狩猎已经以 `ItemId + Count` 保存猎人携带物，营地也已有资源库存和非资源仓库；缺失的是事件奖励到携带物、回营快照到分类仓库的通用传输协议。该协议跨越 Hunt 与 Settlement，必须保持稳定身份、失败关闭和一次性提交。

## Decisions

### 事件只获得非资源物品

`AddItem` 是游戏性效果，继续在 Hunt ActionQueue 的事件 root 中执行。共享事件系统只依赖短生命周期 `IPlayableEventItemCommand`；Hunt 实现验证物品目录、非资源类别、正数量以及当前存活小队执行者。资源仍使用已有 `AddResource`，避免两条资源写入语义重叠。

### 回营 v2 保存聚合物品栈

`HuntRecord` v2 使用稳定 `HuntLootStack`，不保存 Unity 资产引用。HuntManager 聚合所有参战者携带物并按 ID 排序；协议 v1 只接受旧资源清单，v2 只接受新物品清单，混写直接失败，防止恢复时静默丢失数据。

### Settlement 在写入前完成分类预检

GameCore 先根据 Adapter 提供的 `Resource` 或 `StoredItem` 状态构造完整计划并检查未知 ID、重复状态、非法数量和整数溢出。计划成功后，同一 Settlement root 才分类写入资源库存或既有非资源仓库、清空参战者携带物并继续成长、历史与日历提交。

### 3D 回营只投影通用货物决策

世界空间回营卡按物品类型显示聚合货物；远离营地时仍只放弃一个单位，但选择范围扩大到所有携带物。View 只提交稳定物品 ID，权威 Action 会重新读取实时携带物并构造过滤后的快照。

## Risks / Trade-offs

- 事件效果批次沿用既有逐项提交语义；前一效果成功、后一效果失败时不提供通用回滚。本 Change 只保证单个 `AddItem` 和整个回营计划各自预检。
- 非资源物品统一进入现有通用仓库；消耗品专属整理界面留给后续表现任务，不能阻塞回营闭环。
- 版本 0 继续代表旧流程已经转移资源；版本 1 只迁移资源清单，版本 2 才接受通用物品栈。
