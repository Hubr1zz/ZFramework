## Context

营地事件、出猎、狩猎探索、回营和配置化日历均已由各自管理器与 ActionQueue 掌权。旧回归仍会直接调用委托或端口，跳过短按/拖拽阈值、侦察确认桌和世界棋子适配器，因此无法证明玩家看到的 3D 桌面能够连续驱动这些权威事务。

## Goals / Non-Goals

**Goals:**

- 让核心实体卡统一在松手时确认短按，拖拽仍使用 `CardView3D` 阈值生命周期。
- 让地块与资源棋子的鼠标回调和已解析世界指针入口共享同一意图转发逻辑。
- 验证回营随机事件由配置和事件 Runner 决定，不在流程代码或测试中写死具体事件。
- 验证成功回营只推进一个配置季节，Continue 不重复提交且可再次编队。

**Non-Goals:**

- 不新增路线效果、事件规则、内容批量、猎人间物品转移或 Showdown 玩法。
- 不引入第二套输入调度器、UI ActionQueue、MonoBehaviour 权威或 GameManager 拆分。
- 不实现美术、音效和演出打磨。

## Decisions

- `CardView3D.HandlePointerDown/Up` 是实体卡公共短按缝隙；选项、出发、采集和控制卡在 `OnClickReleased` 检查交互状态并转发已有回调。
- 地块与资源棋子的 `OnMouseDown` 负责鼠标专属 UI 穿透检查，再调用 `HandleResolvedPointerClick`；触摸或控制器适配器只有在完成自身射线与 UI 判定后才调用该入口。
- 玩家意图继续进入既有 Hunt/Settlement 端口。输入适配器不直接写地图、携带物、事件、日历或存档。
- 生产 smoke 复用正式 GameManager 组合根与 ZFramework 战役运行态；随机回营事件通过可用实体卡协议收敛，而不是绑定事件 ID。

## Risks / Trade-offs

- [异步演出完成晚于可见状态切换] → 测试按真实时间等待翻面和棋子移动完成，再发出下一次玩家输入。
- [非鼠标适配器误用已解析入口] → 方法名和注释明确调用前必须完成世界命中；鼠标 UI 检查只留在 Unity 回调。
- [随机事件内容变化] → 只验证通用选择/判定/结果协议、完成集合和持久化，不固定具体随机事件。
